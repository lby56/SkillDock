# SkillDock 1.6.0 便携版

支持 Windows 10/11 64 位。管理 Codex、Claude Code、OpenCode、DeepSeek Harness 的本机用户技能。

## 解压即用

1. 把 ZIP **完整解压**到一个可写文件夹。支持中文、空格和 U 盘路径。
2. 双击 `SkillDock.exe`，也可以双击 `启动 SkillDock.cmd`。
3. 应用自动发现当前用户的技能。若使用自定义工具目录，打开「目录设置」。

不需要安装 Node.js、Python 或 npm，不需要管理员权限，不需要登录 SkillDock。
请保留 EXE 旁边的 `resources`、DLL、`locales` 等文件。不能只复制 EXE，也不能直接在压缩软件的临时预览目录运行。

## 四款工具

| 工具 | 默认配置目录 | 启用 / 禁用方式 |
| --- | --- | --- |
| Codex | `~/.codex`；识别 `CODEX_HOME` | 原生 `skills.config`；重启 Codex 后读取 |
| Claude Code | `~/.claude`；识别 `CLAUDE_CONFIG_DIR` | 原生 `skillOverrides` |
| OpenCode | `~/.config/opencode`；识别 `OPENCODE_CONFIG_DIR`、`XDG_CONFIG_HOME` | 原生技能权限规则 |
| DeepSeek Harness | `~/.dsh`；识别 `DSH_HOME` | 技能原生的模型调用和手动调用开关 |

`~` 表示当前使用者的系统用户目录，不是制作压缩包的人的目录。
Harness 也识别 `DSH_AGENTS_HOME` / `~/.agents` 中的一层兼容技能。这类共享来源在 Harness 列中只读；先同步到 Harness 个人目录即可独立切换。用户目录中的 `.system` 和更深层的嵌套目录不视为 Harness 用户技能。

Harness 支持 `<技能>/SKILL.md` 和 `<技能>.md`。禁用会同时关闭模型调用与手动调用；再次启用恢复原调用限制，例如原本只允许手动调用的技能仍只允许手动调用。技能正文和资源保持原样。平铺 Markdown 导出时成为一个 `SKILL.md` 文件夹；其同级依赖需先整理到技能文件夹中。

## 界面

- 界面跟随 Windows 的浅色 / 深色模式。列表占满窗口高度，自带滚动。
- 「四端总览」可按「已齐全 / 待同步 / 含禁用」筛选；点技能名会跳到技能库并定位到该技能。
- 左下角显示上次扫描时间；点「刷新」或按 Ctrl+R 重新扫描，Ctrl+K 聚焦搜索框。

## 多选和同步

- 勾选或 Ctrl 点选多项；Shift 连选；Ctrl+A 全选当前列表；Esc 关闭菜单或取消选择。
- 右键可针对一款工具或四端同时启用 / 禁用。工具专属页面只修改当前工具。
- 「同步全部至四端」先预览缺项，再确认复制；保留已有官方版本和开关。
- 同步规则「Claude Code 自带技能只留在 Claude Code」默认开启：claude.ai 同步下来的 Anthropic 官方技能（标有「Claude 自带」）不会被复制到 Codex、OpenCode 和 Harness，总览中对应列显示「不同步」。OpenCode 会直接读取 Claude 目录，需要在 OpenCode 中禁用这些技能。出现副本或 OpenCode 仍启用时，点提示条上的「按规则整理」：副本进回收站，OpenCode 配置写入前自动备份。规则可在「目录设置 → 同步规则」中关闭。
- 也可按来源选择技能，预览同步差异、导入 / 导出 ZIP。
- 删除和覆盖前的技能进入回收站，可以恢复。

## 路径与移动

- 「目录设置」留空即自动识别。保存收藏等操作不会将自动目录固化为某人的绝对路径。
- 支持 `~/.dsh`、`%USERPROFILE%/.dsh`、`%APP_DIR%/tools/dsh`、`./tools/dsh` 和完整绝对路径。
- `./` 和 `%APP_DIR%` 始终相对于 **SkillDock.exe 所在目录**，与从哪里启动程序无关。
- 指向程序文件夹内的自定义目录会以相对位置保存；移动**整个文件夹**后继续使用新的位置。
- Codex 新写入或调整的技能开关优先采用相对其配置文件的路径，同盘目录一起移动后仍可定位。
- 工具软件自身也必须使用同一配置目录。SkillDock 不替工具改变启动环境变量。
- 外部绝对路径表示一个固定位置：换电脑后需要重新选择，或点击「恢复自动识别」。
- 同步保留技能原始正文、脚本和资源。技能作者写在正文或脚本里的绝对路径、第三方运行依赖不会被盲目替换，需按目标环境调整。

## 管理数据与分享

程序会在自身旁边建立 `data/users/<用户标识>/`，保存设置、收藏、操作记录、配置恢复副本和回收站。
数据按电脑及系统用户隔离，同一用户移动整个文件夹后仍使用自己的数据；其他电脑或用户会自动识别自己的工具目录。
当前用户第一次运行便携版时，会读取并复制自己旧版 `~/.skilldock` 中的设置、操作记录和恢复数据；旧版原件保留。

**发给别人时直接发送原始发行 ZIP。** 发行包不附带制作人的技能、登录信息、配置、历史记录或 `data`。运行过的文件夹可能含使用者自己的管理数据，请勿将它直接重新压缩后公开分享。

这个 ZIP 包含 SkillDock 及其桌面运行时；四款 AI 工具及其登录、插件、MCP 连接和技能依赖由使用者自己的环境提供。项目级配置、Harness 预设、自定义技能提供方等额外来源不属于本机用户目录管理范围。

## 排查

- 没有发现技能：检查「目录设置」的当前解析位置；工具未安装或目录为空时，空列表属于正常状态。
- 无法保存：将整个文件夹放在当前用户可写位置；只读 U 盘或受保护目录不能保存管理数据。
- 换位置后设置不对：先确认完整移动了文件夹，再检查自定义外部路径；可恢复自动识别。
- 打不开：确认使用 Windows x64，并重新完整解压；运行 `启动 SkillDock.cmd` 可以清除外部继承的 Electron 调试启动变量。
# AI 修改 SkillDock（1.6.0）

左侧选择「AI 修改」，输入想增加的功能、要调整的界面或要修复的问题，再点击「生成修改方案」。预览每个文件的修改前后内容，点击「应用修改」保存源码；点击「构建新版」生成独立便携版本，再选择「打开新版并关闭当前窗口」查看效果。构建需要完整源码、Node.js 和已安装的项目依赖；新目录保留当前用户的管理设置与 AI 修改备份。桌面快捷方式可改指向新目录里的 SkillDock.exe。

默认接入本机 Codex CLI，沿用已有登录和模型配置；「测试连接」只检查版本与登录状态。API 连接支持 OpenAI Responses、OpenAI Chat Completions 兼容协议（DeepSeek、通义千问、Ollama 和自定义服务）、Anthropic Messages、Gemini GenerateContent。点击「添加」选择预设，填写 API 地址、模型 ID、API Key，保存后测试连接；API 测试会进行一次简短的模型调用。预设只填写接口形式，实际可用模型与额度以你的服务商账号为准。

API Key 用 Windows 用户加密保存到 ai-settings.json，界面不返回已保存的 Key；换 Windows 用户需要重新填写。生成时将勾选的源码发送到所选服务，每次最多 240 KB。Codex 使用 read-only 沙箱生成 JSON 修改方案，写文件由 SkillDock 在点击「应用修改」后完成。应用修改仅支持 src 下的文本源码与 README.md、PORTABLE.md，不包含工具登录凭据、技能库或运行数据。

「修改备份」保存应用前的原文件，可以恢复；如果文件已有后续编辑，恢复会取消，避免覆盖后续工作。源码恢复后也需要重新构建，当前打开的窗口不会热更新。生成可随时停止，也可切换到其他管理页。
